# Commit conventions

`mesh-app` currently sits inside the parent `loRa` repository and the user decides
when it becomes its own repository (DESIGN §2.1, Appendix E). **Agents do not run
state-changing git commands** (`init`, `add`, `commit`, `checkout`, `switch`, `reset`,
`stash`, `rm`, `clean`, `merge`) unless the user explicitly asks. Read-only commands
(`status`, `log`, `diff`, `show`) are always fine. The rules below apply whenever
commits are made.

## Message format (Conventional Commits, as in convLink)

```
<type>(<scope>)[!]: <imperative summary, lower case, no period, ≤ 72 chars>

<body: what and why, wrapped at 72; reference the WP and DESIGN sections>

Refs: WP-xx[, DESIGN §n.m]
```

- **type**: `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `build`, `ci`,
  `chore`.
- **scope**: the crate, package or area, e.g. `mesh-wire`, `mesh-core/session`,
  `engine-api`, `capacitor-intercom`, `mobile`, `ios`, `android`, `xtask`, `lab`,
  `docs`.
- `!` marks a breaking change of a contract (C1-C9); the body names the contract and
  its new version (e.g. "C1 API_VERSION 1.2").
- English only. No attribution or tool trailers.

Examples:

```
feat(mesh-wire): add GATT chunk reassembly with MTU 23/185/517 vectors
fix(mesh-routing): keep cap at 2 during 5 s up-hysteresis window
docs(bitacora): record WP-04 phase 0 milestone
```

## Content rules

- One work package per commit; never mix two WPs' owned paths in one commit.
- Generated files (bindings, TS types, vectors) are committed together with the
  source change that produced them, regenerated by their xtask command.
- Lockfiles are committed as produced by `cargo`/`pnpm install`; conflicts are
  resolved by re-running the tool.
- Never commit gitignored artifacts (`target/`, `build/`, `dist/`, `node_modules/`,
  `third_party/opus/opus-1.6.1/`, the xcframework, `jniLibs/`), secrets, signing
  material or Lab recordings with location data.
- A commit that lands a milestone carries its BITACORA entry in the same commit.
- Run the WP's `verify` commands from the repository root before committing.
