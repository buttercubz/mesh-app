# Rust conventions

Applies to `crates/*`, `tools/xtask`, `tools/uniffi-bindgen` and `fuzz/`. Design
references: DESIGN §2.3, §2.6, §3, §4, §13.

## Toolchain and workspace

- Toolchain from `rust-toolchain.toml` (channel `1.99.1`, edition 2024, targets
  `aarch64-apple-darwin`, `aarch64-apple-ios`, `aarch64-apple-ios-sim`,
  `aarch64-linux-android`, `x86_64-linux-android`, `wasm32-unknown-unknown`;
  components `rustfmt`, `clippy`). Fuzzing alone uses `cargo +nightly`.
- Workspace `resolver = "3"`; members `crates/*`, `tools/xtask`, `tools/uniffi-bindgen`.
  `fuzz/` is outside the workspace.
- **Exact pins only** (`=x.y.z`). Shared pins live in `[workspace.dependencies]`
  (WP-01) and must equal `scripts/msrv-probe/Cargo.toml` (`cargo xtask check`
  asserts it). Crates use `dep.workspace = true`. A dependency missing from the
  workspace list goes into your own crate's `Cargo.toml` with an exact pin and is
  reported as a deviation.
- Crate manifests come from WP-01 stubs with the DESIGN §3.1 edges and features. Do
  not add a workspace edge in another WP's manifest; file a change request.
- Features: `mesh-voice/opus` optional and not default; `mesh-core` default
  `["opus"]`; `mesh-sim` and `mesh-wasm` depend on `mesh-core` with
  `default-features = false`. Never let `opus-sys` unify into the wasm32 graph.

## Determinism (sans-IO crates)

`mesh-wire`, `mesh-crypto`, `mesh-lab`, `mesh-voice`, `mesh-routing`, `mesh-core`,
`mesh-sim` start `lib.rs` with:

```rust
#![deny(clippy::disallowed_methods, clippy::disallowed_types)]
```

The workspace allows those lints so `mesh-ffi`, `mesh-wasm`, `xtask`, `uniffi-bindgen`,
`opus-sys` and integration tests (`tests/<area>/main.rs`) can use threads and clocks.
In the seven crates:

- no `std::time`, `std::thread`, `getrandom`, `rand::thread_rng`, OS entropy or
  environment reads;
- no iteration over `HashMap`/`HashSet` (lookup-only use is still discouraged; prefer
  `BTreeMap`, sorted `Vec`, fixed arrays) so outputs never depend on hash order;
- randomness comes from an injected `rand_chacha::ChaCha20Rng`; time is a
  caller-supplied `Instant(u64)` in microseconds, monotonic;
- crypto never pulls OS randomness: `snow` with `default-features = false` and the
  engine's `CryptoResolver`; dalek crates without `rand_core`/`getrandom` features;
- no allocation in `push_capture` / `pull_playout` (counting-allocator test).

`cargo xtask check` greps the seven crates' `src/` as a second line of defence.

## Wire and parsing

- All multi-byte integers little-endian; every parser bounded; no recursion; no
  compression. Unknown record types skipped; unknown mesh packet types relayed but not
  delivered (DESIGN §4).
- Malformed input returns an error, never panics. Parsers get a proptest round trip
  and a fuzz target (`fuzz/`, nightly).
- Wire/crypto golden vectors are generated by `cargo xtask vectors` and committed;
  `--check` must show no drift.

## Errors, panics and unsafe

- Library crates return typed errors (`enum Error` with `Display`); no `anyhow` in
  libraries (fine in `xtask`). No `unwrap()`/`expect()` on data from the network, the
  platform or the UI; `expect("reason")` only for true invariants.
- Real-time entry points in `mesh-ffi` carry
  `#![deny(clippy::unwrap_used, clippy::panic, clippy::indexing_slicing)]`: wait-free,
  no allocation, no locks, no logging, never panic.
- Engine-thread panics are caught with `catch_unwind` in the runtime and reported as
  `engine: crashed`; do not rely on that in library code.
- `unsafe` only in `opus-sys`, `mesh-ffi` and `mesh-wasm`, each block with a
  `// SAFETY:` comment. Rust never calls a variadic C function (use the fixed-arity
  shim).

## Style and lints

- `cargo fmt --all --check` and
  `cargo clippy --workspace --all-targets -- -D warnings` must pass.
- Public items of contract crates (C1-C3, C8) have doc comments with units
  (`_us`, `_ms`, `_kbps`, `_b`) in names or docs. Constants come from DESIGN
  Appendix A and cite their section.
- Modules stay focused (a file over ~400 lines is a smell); keep sub-ownership
  boundaries of `mesh-core` (DESIGN §3.3): sub-WPs plug in through their own
  `wire/<module>.rs` and module directory only.
- UI-facing text is never produced in Rust: emit i18n keys plus params.

## Tests

- Unit tests next to the code (`#[cfg(test)] mod tests`); integration tests in
  `tests/<area>/main.rs`, one directory per owning WP.
- Property tests with `proptest` for codecs, windows, routing and floor invariants;
  fixed seeds in CI, random seeds only in the nightly simulator suite.
- Every test asserts something meaningful; no `#[ignore]` to go green. Hardware-only
  behaviour is covered with fakes and simulators and flagged "pending physical" in
  the BITACORA entry.
- Before any build or test that touches `mesh-core`: `cargo xtask fetch-opus`.
